## 1. Supported Database Drivers

`kogen` generates production-ready JetBrains Exposed ORM table definitions and HikariCP connection pools for the following target engines:

| Engine | `kogen.yaml` `database` value | Default Driver Class | Default Port |
| :--- | :--- | :--- | :--- |
| **PostgreSQL** | `postgres` | `org.postgresql.Driver` | `5432` |
| **MySQL** | `mysql` | `com.mysql.cj.jdbc.Driver` | `3306` |
| **MariaDB** | `mariadb` | `org.mariadb.jdbc.Driver` | `3306` |
| **SQLite** | `sqlite` | `org.sqlite.JDBC` | N/A (File) |
| **In-Memory** | `memory` | N/A (`ConcurrentHashMap`) | N/A |
| **Oracle** | `oracle` | `oracle.jdbc.OracleDriver` | `1521` |
| **MS SQL Server**| `mssql` | `com.microsoft.sqlserver.jdbc.SQLServerDriver` | `1433` |

## 2. CLI Configuration (`kogen.yaml`)

You can define database generator settings directly in `kogen.yaml`:

```yaml
project_name: "fintech-banking-api"
package_name: "com.enterprise.fintech"
target_dir: "./output/fintech-banking-api"
database: "postgres"               # Options: postgres, mysql, mariadb, sqlite, memory, oracle, mssql
architecture: "hexagonal"
native_target: "graalvm"

# Database & Infrastructure Generation Options
include_in_memory: true            # Generates InMemoryRepository implementations for unit testing
include_migrations: true           # Generates Flyway SQL V1__init_schema.sql scripts
include_openapi: true              # Generates docs/openapi.yaml
server_port: 8080
```

Alternatively, override database settings via CLI flags:
```bash
.\kogen.exe generate \
  -s ./schema-fintech.dbml \
  --db postgres \
  --name fintech-banking-api \
  --output ./output/fintech-banking-api
```

## 3. Environment Variables & Overrides

The generated Kotlin application loads configuration settings from `src/main/resources/application.yaml` with automatic environment variable overrides.

### `application.yaml` Template
```yaml
server:
  port: ${PORT:8080}

database:
  type: "${DB_TYPE:postgres}"
  url: "${DATABASE_URL:jdbc:postgresql://localhost:5432/fintech_db}"
  user: "${DB_USER:postgres}"
  password: "${DB_PASSWORD:postgres}"
  driver: "${DB_DRIVER:org.postgresql.Driver}"

  # HikariCP Connection Pool Settings
  pool:
    max-size: ${DB_POOL_MAX_SIZE:20}
    min-idle: ${DB_POOL_MIN_IDLE:5}
    idle-timeout-ms: ${DB_POOL_IDLE_TIMEOUT:300000}
    connection-timeout-ms: ${DB_POOL_CONN_TIMEOUT:30000}
    max-lifetime-ms: ${DB_POOL_MAX_LIFETIME:1800000}
    leak-detection-threshold-ms: ${DB_POOL_LEAK_THRESHOLD:2000}

logging:
  level: "${LOG_LEVEL:INFO}"
```

## 4. HikariCP Connection Pool Tuning

For high-throughput enterprise workloads, HikariCP parameters can be tuned via environment variables:

| Variable | Description | Recommended Prod Value |
| :--- | :--- | :--- |
| `DB_POOL_MAX_SIZE` | Maximum connection pool size | `20` - `50` per pod |
| `DB_POOL_MIN_IDLE` | Minimum idle connection count | `5` - `10` |
| `DB_POOL_IDLE_TIMEOUT` | Idle connection max lifetime (ms) | `300000` (5 mins) |
| `DB_POOL_CONN_TIMEOUT` | Connection wait timeout (ms) | `30000` (30 secs) |
| `DB_POOL_MAX_LIFETIME` | Max lifetime of a connection in pool (ms) | `1800000` (30 mins) |
| `DB_POOL_LEAK_THRESHOLD` | Leak detection threshold (ms) | `2000` (2 secs) |

## 5. Database-Specific Complex Setup

### PostgreSQL (AWS RDS / Neon / CockroachDB / Cloud SQL)
```yaml
database:
  url: "jdbc:postgresql://ep-example.us-east-2.aws.neon.tech:5432/fintech_db?sslmode=require&prepareThreshold=0"
  user: "neon_user"
  password: "env_secret_password"
  driver: "org.postgresql.Driver"
```
*Environment Override:*
```bash
export DATABASE_URL="jdbc:postgresql://rds-cluster.amazonaws.com:5432/fintech_db?sslmode=verify-full&sslrootcert=/etc/ssl/certs/rds-ca.pem"
export DB_USER="app_user"
export DB_PASSWORD="secret_password"
```

### SQLite (WAL Mode & File-Based Storage)
For embedded applications, local development, or microservices with zero external network overhead:

```yaml
database:
  url: "jdbc:sqlite:/data/fintech.db?journal_mode=WAL&synchronous=NORMAL"
  driver: "org.sqlite.JDBC"
```

### In-Memory Mode (Zero-Dependency Testing)
When developing locally or running fast CI/CD pipelines without spun-up database instances, `kogen` generates a high-performance `InMemoryRepository` implementation for every entity:

```kotlin
// Thread-safe ConcurrentHashMap storage generated automatically
val usersRepo = InMemoryUsersRepository()
val usersService = UsersService(usersRepo)
```
No external database connections, SQL setup, or container spin-up required!

## 6. SSL/TLS & Security Best Practices

> [!IMPORTANT]
> Never hardcode database credentials in source code or DBML files! Always use environment variables or secret stores (AWS Secrets Manager, HashiCorp Vault, Kubernetes Secrets).

### Connection String Security Options
- **Postgres SSL Modes**: `sslmode=require`, `sslmode=verify-ca`, `sslmode=verify-full`
- **MySQL SSL Modes**: `useSSL=true&requireSSL=true&enabledTLSProtocols=TLSv1.2,TLSv1.3`
- **MS SQL Encrypt**: `encrypt=true;trustServerCertificate=false`

## 7. Database Migrations (Flyway DDL)

`kogen` automatically extracts DBML table definitions, column constraints, Postgres schemas, enums, and foreign keys into a Flyway/Liquibase compatible SQL DDL file located at:

```
src/main/resources/db/migration/V1__init_schema.sql
```

### Schema-Qualified Table Support
If your DBML contains schema scopes (e.g. `auth.users`, `bank.accounts`), the generated migration script initializes schema namespaces automatically:

```sql
-- Auto-generated by kogen CLI
CREATE SCHEMA IF NOT EXISTS auth;
CREATE SCHEMA IF NOT EXISTS bank;

CREATE TYPE auth.UserStatus AS ENUM ('ACTIVE', 'SUSPENDED', 'PENDING');

CREATE TABLE IF NOT EXISTS auth.users (
    id VARCHAR(36) NOT NULL PRIMARY KEY,
    email VARCHAR(255) NULL UNIQUE,
    status auth.UserStatus NULL,
    created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT now(),
    updated_at TIMESTAMP WITH TIME ZONE NOT NULL
);
```
